# Verify Archive Ocellus Trainer

The trainer is a web page: a three.js canvas (`#world`) with the osrs-sdk HUD around it. A user loads the page, sees the arena, their player and Ocellus (NPC 16677) held at tick 0 behind a Start panel, can set keybinds and settings there, presses Start to begin the GET READY countdown, clicks floor tiles to walk (Control-click walks one tile a tick instead of running), switches gear from the inventory, and plays the phase 4 cycle, stepping in and out of the 5x5 under the boss as the void floor changes, stepping around the floor holes, stepping off each explosion mark, praying against each transition attack, attacking around the boss's curse overheads and killing void rifts before they burst. A Settings button and a Restart button sit at the bottom left, with a Pause button beside them during a run; Pause or the P key holds the world tick until Resume, and keybinds and settings work while paused ([features/setup-and-pause.md](features/setup-and-pause.md)). `ab` in `scripts/verify.sh` clicks Start after each page load, and a recipe that reads a page before Start sets `START_ON_LOAD=0`. The Settings button opens a menu with the setup selector, the focus selector, the seed field, Keybinds, the two sound boxes, the Invincible checkbox, the Send anonymous performance data box and What's new, and `open_settings` in `scripts/verify.sh` opens it before a recipe reads or uses one of them. A second click, Escape or a click outside closes it. What's new opens a panel of the changelog's releases; a red dot on Settings marks a release the player has not opened, and the version shows beside the credit line. When a run ends, a result panel shows "Ocellus defeated" with the P4 time or "You died" with the P4 tick, and offers Restart (new seed) and Retry seed (same seed). `bosshp=N` in the link starts P4 at N boss hitpoints, from 1 to the max HP. Invincible starts unchecked; `invincible=on` in the link checks it, and Restart keeps it. While it is checked, hits land as usual, but a hit that would kill the player restores full HP and logs a `death-prevented` event and a chat line. A run without a typed seed draws a fresh one and shows it in the seed field. A hidden phase 3 drill sits behind the build flag `ARCHIVE_P3`: the `browser` stage's dev server sets it, so `?phase=p3` opens P3 and Settings shows a Phase box, and the `production` stage builds without it, so neither shows ([features/p3-drill.md](features/p3-drill.md)). The only backend is the Worker in `src/worker/worker.ts`. It takes the performance summary that a sampled run posts to `/t` and serves every other path from the static assets. Each page reads `sampleRate` from `/telemetry.json` once. The `browser` stage stubs both paths, so no summary leaves the machine. `scripts/verify.sh` runs every stage below and prints `PASS <stage>` or `FAIL <stage>`. It exits non-zero when any stage fails.

```sh
source ~/osrs-sims/env.sh            # Node 22 on this machine; elsewhere use any Node 22
scripts/verify.sh                    # build types test assets browser production
scripts/verify.sh test browser       # any subset, in the order given
```

Run it from the repository root or a worktree. A passing run prints six `PASS` lines and ends with `verify: stop: PID <n> is gone; evidence kept in <dir>`.

## Preconditions

- Node 22 and `agent-browser` 0.34 or later on `PATH`.
- Dependencies: the script first runs `scripts/install-beta-sdk.sh --check`, which prints the commit the installed osrs-sdk packages were built from. When that is not `OSRS_SDK_COMMIT` from the install script, or a package is missing or its `package.json` is unreadable, the script runs `npm ci` and `scripts/install-beta-sdk.sh` itself. The install builds the packs at `OSRS_SDK_COMMIT`. Set `OSRS_SDK_PACKS` to a directory of prebuilt packs to skip that build; the install uses them only when each pack's `gitHead` is that commit, and otherwise refuses them and builds. Any later `npm ci` removes the beta SDK again.
- Assets: `OSRS_CACHE_DIR` (default `~/osrs-sims/cache/openrs2`) holds OpenRS2 cache 2746. `OSRS_CACHE_READER` (default `~/osrs-sims/osrscachereader`) is an osrscachereader checkout with `npm ci` done, on the branch that fixes `EntityOpsDecoder.decodeSubOp`. Without that fix the Fractured Archive NPCs crash extraction.

## Launch

The `browser` stage launches, checks, drives and stops its own instance. To drive a mapped feature by hand, start an instance yourself:

```sh
scripts/verify.sh serve      # webpack dev server on 127.0.0.1:8002
```

It runs with `ARCHIVE_P3=on`. It refuses ports 8000 and 8001, which belong to other trainers, and refuses any port that already has a listener. It records the PID, the process start time, the port, the git revision and the evidence directory in `.verify/current-server`. Ready means `/` answers HTTP 200 and `server.log` contains `compiled successfully`. Set `VERIFY_PORT` for another port. One checkout holds one recorded instance at a time; a second worktree has its own `.verify/`.

## Production

The `production` stage builds the production bundle into `<evidence>/production/`, serves it with `python3 -m http.server` on 127.0.0.1:8003, and opens `?seed=1&invincible=on` in its own session. Set `VERIFY_PRODUCTION_PORT` for another port; it refuses 8000, 8001, `VERIFY_PORT` and any port with a listener, and stops the static server by its PID. A production build has no probe, so an init script records the four minimap orb numbers (hitpoints, prayer, run, special) that each frame draws. The stage never clicks Start, so the page is watched in the set-up state, which draws every frame without ticking, for 20 s after the orbs first draw. It is then reopened with every request for a root-level `.png`, the SDK's bundled images, aborted until the page first requests one. Each check fails on a page error, on a frame since the first that drew no orb numbers, or on a first frame other than `["99","99","100","100"]`. The dropped images must each be requested again and answer 200. The stage builds with `ARCHIVE_P3=off`, then opens `?phase=p3&seed=1` and checks that it draws P4's entry boss bar and that Settings has no Phase box.

## Doctor

```sh
scripts/verify.sh doctor
```

Read-only. It passes when the recorded PID is alive with its recorded start time, that PID owns the port, `/` loads completely with the title `Archive Ocellus Trainer`, and `/osrs-assets/manifest.json` loads completely and contains `npc-16677`. It also warns when HEAD or tracked files changed since launch; webpack has reloaded them, but the recorded revision no longer names what you are driving. Run it first whenever anything looks wrong, and never drive an instance this checkout did not start.

## Drive

Use a named agent-browser session so you never touch another agent's browser:

```sh
export AGENT_BROWSER_SESSION=archive-ocellus-$(date -u +%Y%m%dT%H%M%SZ)
agent-browser set viewport 1280 800
agent-browser open "http://127.0.0.1:8002/?seed=1&specialSelection=replay-v2"
agent-browser wait --fn "window.__archiveOcellusProbe?.snapshot().tick >= 8" --timeout 90000
```

Drive with real input only: page loads, `agent-browser mouse move/down/up` on the canvas, and visible elements by CSS id. The canvas has no accessible children, so tiles are reached by pixel position relative to `agent-browser get box "#world"`. The camera centres on the player and faces south, so screen left is east and screen up is south. At a 1280x800 viewport, the point `WALK_CLICK_LEFT_PX` (160) left of and `WALK_CLICK_UP_PX` (50) above the canvas centre is a floor tile; from the spawn tile (5, 1) the player walks to `WALK_TARGET_TILE` (8, 3). The three constants sit together at the top of `scripts/verify.sh`. The `browser` stage fails when the click resolves to any other tile, so a changed viewport, camera or default setting shows up as a failure. It does not pass silently.

Restart and the `Focus` selector reload with a fresh seed unless the seed box was typed in. A recipe that checks a seeded run after either one first types the box's own value back with `agent-browser fill "#seed" <the value of #seed>`, as `keep_seed` in `scripts/verify.sh` does.

A focus drill starts 5 ticks before its mechanic first acts, and the full fight and the `floor-holes` drill start at P4 tick 0. A recipe that needs a drill's earlier ticks adds `drillStart=cycle-start` to the link; Restart keeps it.

Development builds expose a verification probe, `window.__archiveOcellusProbe`. `snapshot()` returns a fresh copy of `{ ticking, tick, player, destination, fight, rejected, panel, menu, icons }`: `tick` is the SDK world tick, `fight` is `{ run, boss, player }` with the P4 tick and phase in `run`, the boss's HP and Defence in `boss` and, in `boss.visible`, whether the renderer draws the boss model, and the worn and carried item ids and the special energy in `player`. `rejected` lists URL options the drill ignored. `panel` names the open side-panel tab (`INVENTORY`, `PRAYER`, `SETTINGS` and so on, or `null` for a tab with no name) and the keys bound to the inventory, spellbook, prayer, equipment and combat tabs. `menu` lists the lines of the open right-click menu, without `Cancel`, or is `null` when no menu is open. `icons` maps the id of every carried and worn item to the path and decoded size of the sprite the side panel draws for it. `log()` returns the fight log: a header with the seed and every resolved choice, one row per boss step with its phase, beats, inputs and events, and `pauses`, one `{ at, ms }` per pause with the world tick it held and its length. Each row samples the player and the boss HP twice. `playerAtBossStep` and `bossHp.atBossStep` are read when the boss steps, after prayers publish and before hits land. `playerAtPostTick` and `bossHp.atPostTick` are read in the region's `postTick`, after every unit has moved. `tileCentre({ x, y })` returns a whole canvas pixel whose click selects that floor tile at the current camera, from the SDK's `Viewport.projectTile`, or `null` when no pixel on the canvas selects it. The probe has no setters. Use it to record state the UI does not show. Never use it, `eval`, or SDK internals to change state; a proof that mutates the world through code proves nothing about the user path. Production builds (`npm run build`) do not contain the handle.

Per-feature recipes are in [features/README.md](features/README.md). [scenarios.md](scenarios.md) maps each mechanic to its Vitest and browser scenarios, the input each one sends and the source of its expected values, and lists the tests that still bypass real input.

A browser proof captures the action and the resulting state, not only the last screen. A test count of zero fails the `test` stage. A page error fails the `browser` stage, and so does a failed or empty screenshot, state, console or page-error capture. Prove that a new or changed browser check can fail: break the product or the check on purpose, run `scripts/verify.sh browser`, record that the check fails, then restore it.

## Cleanup

```sh
agent-browser close
agent-browser --session "${AGENT_BROWSER_SESSION}-autoplay" close
agent-browser --session "${AGENT_BROWSER_SESSION}-mobile" close
scripts/verify.sh stop
```

`stop` signals only the recorded PID, and only while its start time still matches, so a reused PID is never signalled. It waits for the process to exit, confirms the port is free, then removes `.verify/current-server`. It never deletes evidence. Never stop the server by process name or pattern. Run cleanup after every failed attempt too. The `browser` stage does all of this itself, including on Ctrl-C. It stops only an instance it started. When `.verify/current-server` already records an instance, for example one from `scripts/verify.sh serve`, the stage fails and leaves that instance running.

## Helpers

- `scripts/verify.sh [build] [types] [test] [assets] [browser] [production]`: the stages; no argument runs all six. `types` runs `npm run typecheck`: strict `tsc` over `src` and `test`, then `scripts/check-types.mjs`, which fails on `any`, `as` casts other than `as const`, non-null and definite-assignment `!`, `@ts-` suppression comments in `src`, imports of the fight's internal modules from outside `src/content/ocellus/js`, test files inside it, and imports in `src/sim` of anything outside `src/sim`. Tests live in `src/content/ocellus/tests` and drive the region.
- `scripts/check-types.test.sh`: planted violations and a clean control for `check-types.mjs`. Run it after changing the rule check; CI runs it too.
- `scripts/verify.sh serve | doctor | stop`: a manual instance, as above.
- `scripts/install-beta-sdk.sh`: installs the beta SDK packages with `--no-save`. A build stamps the commit it checked out into each pack's `gitHead`, and the install ends by checking that every installed package names `OSRS_SDK_COMMIT`. `--check` runs only that check. CI calls it without `OSRS_SDK_PACKS`, so it builds from the pinned commit.
- `scripts/install-beta-sdk.test.sh`: stale or partial installs and prebuilt packs from other commits, with git, the SDK build and the registry `npm ci` stubbed. The fixture app's own build runs for real. Run it after changing the install or `ensure_deps` in `scripts/verify.sh`; CI runs it too.
- `review-ratchet/classes.json`: review findings seen twice, each with the check that now enforces it. CI runs `review-ratchet/checks/shell-test-runs-entry.mjs` (every shell test prints `PASS <case>` or `FAIL <case>` for each case, followed by that case's output, in which the case prints `ready <case>` once its setup is done; when its script breaks a policy listed in `review-ratchet/guarded-policies.json` it reports the same cases, with one that printed its ready line in both runs failing an assertion after it, printing a line that starts `ASSERTION FAILED: `; a new shell test or guarded script needs an entry there) and `review-ratchet/checks/replay-controls.mjs --base REV` (the head's test changes, replayed over the base, keep every unchanged test passing). `RenderPaths.test.ts` and `BossStates.test.ts` use the other two checks' rules. Before citing a base replay as regression evidence, run `replay-controls.mjs --base "$(git merge-base origin/main HEAD)"`.

The `assets` stage regenerates the inventory icons of the trainer's own items and of the SDK items listed in the gear recipe's `sdkIcons` in `public/osrs-assets/item-icons/` on every run; `src/itemIcons/` renders them from each item's inventory model in the same cache. It skips the model extraction when `public/osrs-assets/manifest.json` already contains every NPC, a player model for every item and every spotanim the asset config declares, from `openrs2:2746`, its sound pack holds every sound the config declares, and `scripts/extract-sprites.mjs --check` finds every sprite PNG listed in `src/assets.ts`. The boss's P4 poses and the transition attack tells come from the presentation recipe in `OcellusTimings.ts`; a pose added there is extracted on the next rebuild. The trainer's gear item ids come from the gear recipe in the same file, the orb spotanims from its `lifeforceOrb.look`, the cue sounds from its `presentation.sounds`, the overhead icons from its `presentation.overheadIcons`, and the void rift (NPC 16678), its poses and its burst flare from its `rifts`. The SDK's asset tool has no sprite category, so `npm run assets` ends with `scripts/extract-sprites.mjs`, which writes the head icons from the cache's sprite index to `public/osrs-assets/sprites/`. The stage runs only `npm run assets` before its checks, the same command the hosted build runs, so a sprite that command does not write fails the stage. Delete `public/osrs-assets/` to force a rebuild. Extracted assets are never committed.
